## B. What's genuinely solid — lead with these in an interview

1. **The Cedar authorization path is real, not decorative.** `cedar-wasm` runs *inside* the Lambda (`initSync` loads an embedded base64 WASM blob at `embedded.gen.ts`), evaluates the actual `policy.cedar` file against principal/action/resource entities built from server-verified data (the caller's email comes from `AdminGetUserCommand` against Cognito, never from the client), and every decision — allow or deny — is logged as structured JSON before any throw. This is the one piece of the architecture that's simultaneously interesting to explain (why Cedar over hand-rolled `if` checks: policy is data, auditable, testable independent of the handler) and fully demoable on camera via `aws logs tail`.
2. **The slot finder is real interval math, not a stub.** `find-slots/handler.ts` builds actual busy-interval sets per section/professor/irregular-student-group, computes free candidate windows, ranks them with explainable scoring (lunch avoidance, 9–5:30 window, "edge of day" penalty), and produces a genuine blocking explanation by testing "what if this one party were excluded" for every hard party. This is not an LLM call; it's the whole reason the brief says "no chatbot has this data at once."
3. **Ingestion honesty is already written down, not just claimed here.** `README.md`'s "How the timetable reading works, honestly" section pre-empts exactly the question a judge or interviewer would ask, and states plainly what's automatic, what's checked, what falls back to a person, and what was hand-verified (IT Sem 3/5 was hand-structured first, then the deployed reader re-read the same sheets and matched those rows exactly — a real cross-check, described in the README, not fabricated for this doc).
4. **The data model has one honest wrinkle worth naming up front:** the schema in production (`StudentSection`/`RollRange`/`Enrollment`) is the *first* data model. A second, more principled one (`Course`/`Offering`/`Registration`) is fully designed in `docs/DATA-MODEL.md` but was never built — that doc is dated after the last code commit in the log. If asked "what would you build next," this is the honest, specific answer, not a vague "more features."
